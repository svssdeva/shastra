# Trishul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship `trishul-mcp` — a Rust binary speaking MCP over stdio that gives Claude live OS-level visibility into a Linux machine (processes, network, USB, GPU, host).

**Architecture:** Cargo workspace, one bin (`trishul-mcp`) + one or two libs. `rmcp 1.7` for protocol + tool routing. `procfs` + `nix` for `/proc` reads. Each collector is independently testable via a `Source` trait that can be backed by a fixture filesystem.

**Tech Stack:** Rust 2024 · rmcp · tokio · procfs · serde · schemars · thiserror · tracing · clap. (Linux-only MVP.)

**Spec:** `docs/superpowers/specs/2026-05-28-trishul-design.md`

**Project root:** `/mnt/shared/Projects/yolo/trishul/`

## File structure

```
trishul/
├─ Cargo.toml                        # workspace
├─ rust-toolchain.toml
├─ rustfmt.toml
├─ .gitignore
├─ README.md
├─ crates/
│  └─ trishul-mcp/
│     ├─ Cargo.toml
│     ├─ src/main.rs                 # CLI + MCP entry
│     ├─ src/server.rs               # ServerHandler impl + tool router
│     ├─ src/collectors/
│     │  ├─ mod.rs
│     │  ├─ host.rs                  # host_info
│     │  ├─ proc.rs                  # process_tree, proc_snapshot, process_detail
│     │  ├─ net.rs                   # network_listeners
│     │  ├─ usb.rs                   # usb_devices
│     │  └─ gpu.rs                   # gpu_telemetry (stretch)
│     ├─ src/types.rs                # Output<T>, errors
│     ├─ src/selftest.rs             # --selftest CLI subcommand
│     └─ tests/
│        ├─ mcp_loop.rs              # integration: spawn bin, send tools/list
│        └─ fixtures/                # synthetic /proc + /sys trees
└─ docs/
   ├─ CLAUDE_CONFIG.md
   └─ TOOLS.md
```

Decision: keep everything in **one crate** (`trishul-mcp`) for MVP. Splitting collectors into separate crates pays off later if compile time blows up; not yet. Each collector is a module — same isolation, simpler workspace.

## Phase 1 — `host_info` collector

### Task 1.1: types module

- [ ] `src/types.rs`: `Output<T>`, `TrishulError`, helper `output()` ctor

### Task 1.2: host collector

- [ ] `src/collectors/host.rs`: read `/proc/uptime`, `/proc/meminfo`, `/proc/loadavg`, `uname()` via `nix`, return structured snapshot. Pure function `collect_host_info() -> Result<HostInfo, TrishulError>`. Unit test against a fixture path (the actual `/proc` works in CI too).
- [ ] Wire into server as tool `host_info`.

### Task 1.3: Manual verification

- [ ] `cargo run --quiet -- selftest host_info` → prints a real snapshot of the dev box.

## Phase 2 — `proc` collectors

### Task 2.1: process_tree

- [ ] `src/collectors/proc.rs`: walk `procfs::process::all_processes()`, build adjacency (PPID → children), produce tree rooted at `root_pid` (default 1) with breadth-first traversal capped at `max_nodes` (default 5000). Each node: pid, ppid, comm, exe (best-effort), cmdline, user (resolved via uid → name), rss_kb, threads.

### Task 2.2: proc_snapshot

- [ ] Top-N by CPU% (computed from two samples 100ms apart) or RSS (single sample).

### Task 2.3: process_detail

- [ ] One PID → status, env (if perms), cwd, exe, fds (limit), limits, cgroup.

Each gets unit tests with a fixture `/proc` tree.

---

## Phase 3 — `net`, `usb`, `gpu` collectors

### Task 3.1: network_listeners

- [ ] Parse `/proc/net/tcp{,6}` and `/proc/net/udp{,6}`. Resolve inode → PID by scanning `/proc/*/fd/*` for socket inodes (cap work — limit to first match).

### Task 3.2: usb_devices

- [ ] Walk `/sys/bus/usb/devices/*` for `idVendor`, `idProduct`, `product`, `manufacturer`, `bcdDevice`, port topology. Resolve vendor names from `/usr/share/hwdata/usb.ids` if present.

### Task 3.3: gpu_telemetry

- [ ] If `nvml-wrapper` features in (optional dep), use it. Else shell `nvidia-smi -q -x` and parse XML. AMD/Intel: `/sys/class/drm/card*/device/`.
- [ ] All paths fail soft — warnings, not errors.
